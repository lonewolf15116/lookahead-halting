The six natural benchmarks total 29,353 questions.

- **Dataset versions.** Each HF dataset's commit SHA is recorded the first time it is downloaded on the laptop and written to `data/manifests/questions.json`. Extraction rebuilds the questions and must reproduce the recorded question-set sha256, so a silent dataset change stops the run.
- **Primary metric.** Each benchmark's prediction at loop t is the argmax of its primary metric's score: length-normalised log-likelihood (acc_norm) for the cloze tasks, raw log-likelihood (acc) for the letter tasks. This choice is fixed here. It does not depend on the qualification about which metric Ouro's paper reports. Both metrics are still stored.
- **MMLU aggregate.** Reported both ways: weighted by subject size (lm_eval's group default) and as a plain average over subjects.
- **Free reproduction check.** Phase 1 produces per-loop accuracy for ARC-E, HellaSwag, MMLU and CSQA. These are compared with the paper using the same ±2-point rule as Gate 0. This is a sanity check, not a gate. If a benchmark misses, extraction for that benchmark is investigated before Gate 1 uses it.
- **Benchmark six.** OpenBookQA has no paper reference. Winogrande does (56.99 / 66.69 / 71.35 / 72.30), but its two options have different contexts. There is then no shared question state to probe, and that breaks the per-question halting unit. Section 9 asks you to decide.

## 2. Synthetic tasks

Both are generated by `scripts/make_synthetic.py` with a recorded seed. Answers are single tokens in Ouro's tokenizer, which I checked: digits are split one per token, " even" and " odd" are one token each, and each bit is one token. So both tasks use the letter-style single-pass scoring. Every task uses 5 shots at the same difficulty, drawn from a separate exemplar pool generated with a different seed. At every level, evaluated items are unique, exemplars never equal an evaluated item of their level, and the 5 exemplars in one prompt are distinct. Synthetic prompts are tokenised as written: context alone, then context + choice. lm_eval's trick of moving trailing whitespace into the continuation is not applied, because the modarith prompt deliberately ends in the space token that Ouro's tokenizer always puts before a digit.

**Modular arithmetic.**
- **Grammar.** Every expression is fully parenthesised and left-associative, `(((a op1 b) op2 c) op3 d) mod 7 = `, so the order of evaluation is explicit and needs no precedence rules. A two-operand item is `(a op1 b) mod 7 = `. The answer is the exact integer value of the expression, reduced with Python's `% 7`, which always gives a result in 0-6, even for negative intermediate values.
- **Operands and operators.** Operands are uniform on 0-99, and operators are uniform over `+`, `-` and `*`.
- **Prompt and options.** The prompt ends in a space, so the answer is one digit token, chosen from the digits 0-6 (7-way choice, 14.3% chance).
- **Token boundaries.** These are checked on the actual full prompts, not on isolated strings. For every generated item and every option, tokenising the whole prompt plus option must give exactly the prompt's own tokens followed by one option token. Prompts are tokenised the way the scorer does it, and any item that fails is a generator error.
- Difficulty is the number of operands, n ∈ {2, 3, 4, 5}, with 500 items per level and 2,000 in total.
- Seeds: evaluated items 20261020, exemplars 20261021.

**Parity.**
- Prompt: `Bits: 0110101\nNumber of 1s is`. The options are " even" and " odd", so chance is 50%.
- Bit strings are uniform random, balanced by rejection so each level has 50% even answers.
- The same token-boundary check applies: the full prompt plus " even" or " odd" must equal the prompt's tokens followed by exactly one option token.
- Difficulty is the bit length, L ∈ {10, 12, 16, 20}, with 500 items per level and 2,000 in total. The draft had L = 4 and 8, but those levels have only 16 and 256 distinct strings, so 500 unique items cannot exist. Repeated items would put identical questions in both train and test.
- Seeds: evaluated items 20261022, exemplars 20261023.

**Learnability rule, fixed in advance.** Chance here means the majority-class rate of the level. Modarith answers are not uniform (residue 0 is most common), so that rate is 17.8-20.6%, not 14.3%; for parity it is 50%. A synthetic task, or a difficulty level within one, whose loop-4 accuracy is below chance + 10 points is reported as "not solved by Ouro in this format". It is then dropped from Phases 2-3, because label-based oracles on near-chance answers measure noise. Synthetic tasks are always reported separately and never enter the Gate 1 verdict (section 8).

## 3. Splits

- **Strata.** Splits are made within each stratum: each benchmark, each MMLU subject, and each synthetic difficulty level.
- **Assignment.** Within a stratum, questions are sorted by `sha256("lh-split-v1|" + benchmark + "|" + doc_id)`. The first 60% (rounded) go to train, the next 20% to validation and the rest to test. This is exact stratification, it does not depend on load order, and it is decided before any probe rows exist.
- **Manifest.** `data/manifests/splits.csv` (benchmark, stratum, doc_id, split) and its sha256 are committed before extraction starts. It is CSV so it can be committed; parquet is gitignored. Each benchmark's question set also gets a sha256 (`data/manifests/questions.json`), which extraction re-checks.
- **Disjointness.** Splits are question-disjoint. Each question's 4 loops stay in one split. Few-shot exemplars come from outside the evaluated questions and are shared as context by every split, which does not leak labels.
- **Already seen.** The ARC-C test questions were looked at in aggregate in Gate 0 (accuracy and transition counts). No threshold or feature was chosen from them.

## 4. Extraction

**Halting unit and packed scoring.**
- Each question is one forward pass per loop. Few-shot context, question and all options are scored together, as PROTOCOL.md requires.
- Letter tasks (MMLU, CSQA, synthetic): the options are single tokens after a shared context. One pass gives every option's log-likelihood from the logits at the last context token. This is exact by construction.
- Cloze tasks (ARC, HellaSwag, OBQA): the context and every option's tokens go in one sequence. Each option attends to the context and to itself only, through a custom 4-D attention mask, and its position ids restart at the context length. Ouro uses full attention in all 24 layers with no sliding window, so the mask is plain.
- **Mask construction.** The mask is built with transformers' own `create_causal_mask(..., and_mask_function=...)` using a segment id per token, so its format suits whichever attention backend is active. The positions passed to mask construction are a plain 0..L-1 range. Otherwise transformers would read the restarted option positions as separate packed documents, and the options would lose sight of the context.

**Packed-scoring acceptance (all must pass; otherwise per-option scoring is used, whatever the runtime)**

| # | Test | Where | Pass if |
|---|---|---|---|
| P1 | Per-option log-likelihood, every loop | float32 tiny Ouro (unit test) | max abs diff from per-option scoring ≤ 1e-4 |
| P2 | Branch isolation: changing one option's tokens leaves the other options' scores unchanged | float32 tiny Ouro | other options' log-likelihoods and the shared hidden state bit-identical, or diff ≤ 1e-5 |
| P3 | Mask and positions: the mask equals the reference boolean matrix (causal; context sees context only; option k sees context plus option k); option position ids are `len(ctx) + j`; no padding inside the packed row | unit test | exact |
| P4 | Shared hidden state h_t at the last context token equals the context-only pass, every loop | float32 tiny Ouro; BF16 pilot | float32 ≤ 1e-5; BF16 reported (max abs, cosine) |
| P5 | Per-option log-likelihood against the Gate 0 per-option cache, all 4,687 ARC-C requests, every loop | BF16 pilot | reported: median, p99 and max abs diff per loop |
| P6 | Rankings: top answer, full option ranking, and confidence (max p_t) against Gate 0 per-option scores | BF16 pilot | top answer identical on ≥ 99% of questions per loop; confidence p99 abs diff reported |
| P7 | Accuracy | BF16 pilot | acc and acc_norm within 0.5 points of Gate 0 at every loop |
| P8 | Target sensitivity: D_t and F_t from packed scores against the same quantities from the Gate 0 per-option scores | BF16 pilot | F_t agreement ≥ 98% per step; D_t rank correlation reported |

BF16 per-option scoring is not bit-reproducible either: Gate 0 showed logit differences up to 0.06 from shape changes alone. So P5 and P8 have no hard threshold beyond P6 and P7. Their numbers go to the reviewer, who makes the call.

**Stored per question, per loop t = 1..4** (Parquet, one shard per benchmark):

| Field | Definition |
|---|---|
| `h_t` | Hidden state after loop t's final norm, at the last context token, which is the same for every option. 2048 values, float16. |
| `opt_ll_t`, `opt_lln_t` | Raw and length-normalised option log-likelihoods (normalised by characters, as lm_eval does). |
| `p_t` | Option distribution: softmax over the primary score. |
| `pred_t`, `correct_t` | argmax of p_t, and whether it equals the target. |
| `conf_t`, `ent_t` | max p_t and the entropy of p_t (nats). |
| `vent_t` | Full-vocabulary entropy at the last context token. |
| `gate_t`, `cdf_t` | Ouro's exit-gate logit and its cumulative exit probability. |
| `ms_t` | Measured wall-clock time for loop t (CUDA-synchronised). |
| question-level | `n_tokens`, `n_options`, `target`, `status`, `split`, `subject/level`. |

- **Storage.** About 33.4k questions × 4 loops × 4 KB ≈ 0.55 GB for `h_t`, plus small scalars. Full-vocabulary logits are reduced to targets in memory and never stored.
- **Option states.** Hidden states at option tokens are not stored. They can be recomputed if a later phase needs them.

## 5. Targets (for t = 1..3, plus the final-loop forms)

| Target | Definition |
|---|---|
| D_t | KL(p_t ‖ p_t+1) over options. This is the primary change target. |
| D_t^vocab | KL over the full vocabulary between loop t and t+1 at the last context token (log_softmax in float32). |
| K_t | KL(p_t ‖ p_4) over options: distance to the final loop. K_t^vocab is the same over the full vocabulary. |
| F_t | 1 if pred_t ≠ pred_t+1. F_t^final = 1 if pred_t ≠ pred_4. |
| T_t | Correctness transition t→t+1 ∈ {C→C, C→W, W→C, W→W}. T_t^final is the same for t→4. |
| ℓ_t, G_t | ℓ_t = −log p_t(target); G_t = ℓ_t − ℓ_t+1, the loss gain. |

The Gate 1 report gives transition tables (counts, percentages, net change with a bootstrap 95% interval) for every adjacent step and for t→4, per benchmark and pooled, as the Gate 0 report now does for ARC-C.

## 6. Policies and baselines

Every policy halts at the earliest loop t ∈ {1, 2, 3} whose rule fires. If none fires it runs to loop 4. Its answer is pred at the exit loop, and its cost is the number of loops executed.

| Policy | Rule at loop t | Loops executed | Deployable |
|---|---|---|---|
| Fixed-k, k = 1..4 | always exit at k | k | yes |
| Confidence | conf_t ≥ τ | t | yes |
| Entropy | ent_t ≤ τ | t | yes |
| Native gate | cdf_t ≥ q (Ouro's own exit rule) | t | yes |
| Deployable measured-KL | after running loop t+1: D_t ≤ τ, then answer with pred_t+1 | t+1 (minimum 2) | yes |
| Retrospective measured-KL | D_t ≤ τ, answer with pred_t, loop t+1 not charged | t | **no**, analysis only |
| Stable-final oracle | earliest t with pred_t = pred_t+1 = … = pred_4 | t | **no**, uses future loops |
| Earliest-correct oracle | earliest t with correct_t; if never correct, exit at 4 | t | **no**, uses labels |

- **Stable-final oracle.** For a question correct at loop 4, this is the protocol's earliest-stable-correct oracle. For a question wrong at loop 4, it exits once the final wrong answer is settled. So its accuracy equals fixed-4 exactly, and its saving is pure headroom at no accuracy cost. The earliest-correct oracle is the optimistic upper bound and is reported alongside.
- **Threshold grids.** τ and q each run over 50 quantiles of the statistic's validation distribution, pooled over loops 1-3. The full grid is reported.
- **Choosing a threshold.** A baseline's operating point is the threshold that saves the most on validation while losing no more than 1 point of accuracy against fixed-4 on validation.
- **Cost.** Loops executed is the primary cost. Estimated wall-clock is reported next to it: the sum of `ms_t` over executed loops, plus the decision overhead (zero for scalar rules, and for deployable KL, the loop it has to pay for). True early-exit latency waits for Phase 3. Oracle and retrospective rows are drawn as dashed reference lines and never ranked against deployable ones.
- **Learned baselines.** The probes and the small model on confidence, entropy and gate are Gate 2 work. They are not fitted in Phase 1.

## 7. Failures and timeouts

- **Status.** Each question gets one of: `ok`, `oom`, `timeout` (60 s wall-clock for 4 loops, about 15× the expected time), `nonfinite` (NaN or inf in logits), or `bad_target`.
- **Counting.** A failed question stays in every denominator. It counts as wrong at every loop and as executing 4 loops under every policy and oracle, which is the conservative choice for headroom.
- **Validity.** A benchmark with more than 1% failures does not enter Gate 1 until the cause is fixed and the benchmark re-extracted. Failure counts are reported per benchmark.
- **Resuming.** Extraction resumes from per-benchmark shards keyed by doc_id. A rerun never overwrites an `ok` row.

## 8. Gate 1 decision rule

Gate 1 is computed on the **test** split, with thresholds chosen on validation as in section 6. It touches test once for this gate. The six natural benchmarks are combined by an unweighted average across benchmarks, so MMLU and HellaSwag (82% of questions) do not dominate. The question-weighted average is also reported.

- **S_or**, the final-answer-preserving oracle saving: 1 − (mean loops executed by the stable-final oracle) / 4. It is the saving available without changing any question's final answer. It is **not** the largest accuracy-preserving saving possible. A policy could stop at an earlier answer that differs from the final one and still match or beat fixed-4 accuracy over the whole dataset. Read the 25% threshold with that in mind. The earliest-correct oracle is reported as a looser optimistic reference.
- **Qualifying a baseline.** Each cheap baseline is fixed-1, fixed-2, fixed-3, confidence, entropy, native gate or deployable measured-KL. A baseline qualifies only if some operating point loses ≤ 1 point of accuracy against fixed-4 **on validation**. For thresholded baselines, that point is the one with the largest validation saving under the constraint. A fixed-k policy has a single operating point and qualifies only if fixed-k itself meets the constraint on validation. Fixed-1 or fixed-2 cannot qualify just because they save many loops.
- **Freezing.** The qualified operating points are frozen on validation and evaluated once on test. Test accuracy is never used to select or exclude a baseline.
- **S_b** is a qualified baseline's test saving. Its test accuracy loss against fixed-4 is reported next to it. A test loss above 1 point is reported as a constraint violation, but the baseline stays in R.
- **R (primary)** = max S_b over the qualified baselines, divided by S_or. If no baseline qualifies, R = 0.
- **R_unc (secondary diagnostic only)**: the same ratio using each baseline's largest-saving point under the 1-point constraint applied on **test**. It shows how much the validation-to-test shift matters. It never decides the gate.
- **PASS** if S_or ≥ 0.25 and R < 0.75, which is PROTOCOL v1.1 unchanged, judged on the point estimates. Here R is the primary, validation-qualified ratio.
- **Uncertainty.** 95% intervals for S_or, each S_b and R come from a paired, question-level bootstrap with 2,000 resamples, stratified by benchmark, seed 0.
- **Labelling.** If a threshold lies inside its interval, the verdict carries the label **MARGINAL** next to PASS or FAIL. A marginal result goes to you for a decision rather than being read as clear.
- **Per benchmark.** S_or, R and the transition tables are reported per benchmark. Gate 1 can pass overall while failing on individual benchmarks, and that is reported as a finding.

**Fixed-3 risk, stated now.** On ARC-C, fixed-3 loses only 0.26 points against fixed-4 (Gate 0). If it also stays within 1 point on the pooled validation set, it qualifies with a saving of exactly 25%. Then R < 0.75 needs S_or > 33.3%. A learned policy has to justify itself against simply dropping a loop.
